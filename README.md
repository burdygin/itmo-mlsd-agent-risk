# Риск вызовов агента — IAM 604

Учебный ML-проект Даниила Бурдыгина для ML System Design, ИТМО, осень 2026.
Модель оценивает риск следующего вызова инструмента ИИ-агентом с учётом задачи,
ресурса и предыдущих действий. Оценка помогает отправлять опасные вызовы на
подтверждение. Проверка прав и ограничение возможностей выполняются отдельно.

## Задача и границы

Внутри разрешённого доступа агент может выбрать неверный объект или сочетать
чтение чувствительных данных с внешней отправкой. Одинаковые права ещё не
означают одинаковый риск для текущего поручения. Сравниваем правила,
логистическую регрессию и модель на табличных признаках по полноте обнаружения
опасных действий при ограниченном числе ложных тревог.

Связь с [проектом Enterprise IAM 604](https://talenttrack.aitalenthub.ru/projects/604) —
исследование дополнительного сигнала риска на шлюзе инструментов. Роль автора,
интерфейс интеграции и использование темы ещё требуют согласования с руководителем.
Дизайн не объявляет эту ML-часть требованием команды проекта 604.

**Состояние ДЗ1:** подготовлен дизайн. Данных пока нет.
Обучение и измерение результатов ещё предстоят. Тестовый стенд и обучение относятся к следующим итерациям.
Данные планируются только синтетические; открытые наборы допустимы после
проверки лицензии и состава. Рабочие материалы автора и данные Univermag исключены.

## Локальная работа

Нужны Git, Node.js 22 или новее, npm и Python 3.11 или новее для pre-commit.
Python нужен инструменту проверки; ML-стек этой итерацией не установлен.

```bash
npm ci
uv tool install pre-commit==4.7.0
pre-commit install
pre-commit run --all-files
```

Если `uv` не установлен, вместо второй команды: `pipx install pre-commit==4.7.0`.
Установленный бинарь `pre-commit` должен быть доступен через `PATH`.

```bash
npm run format        # форматирование Markdown, YAML и JSON
npm run format:check  # проверка форматирования
npm run lint         # структура Markdown
```

Pre-commit также проверяет YAML/JSON, окончания строк, конфликтные маркеры
и крупные файлы. GitHub Actions запускает тот же набор проверок на push и PR.
Тесты модели появятся вместе с её реализацией; зелёный линтер не измеряет качество ML.

## Порядок сдачи

Работа находится в `hw_1`; `main` содержит начальный коммит для открытия PR.
По [условию ДЗ1](https://gist.github.com/pacifikus/47424379293e0874859354ecd130ba13)
срок сдачи — **29.10.2026 20:00 МСК**, срок двух кросс-ревью —
**05.11.2026 20:00 МСК**. Баллы выставляются после завершения требуемых ревью.
PR из `hw_1` в `main` объединяется после приёмки. Публичная публикация и
регистрация в таблице курса выполняются автором.
